# OSINT Telegram Bot — Maigret + SpiderFoot

Telegram-бот для работы с открытыми источниками:

- **Maigret 0.6.5** — поиск публичных профилей по username.
- **SpiderFoot 4.0** — сбор открытой информации по доменам, IP и другим разрешённым целям.
- **Telegram Stars** — каждый OSINT-запрос оплачивается отдельно.

## Оплата

По умолчанию один `/username` или `/scan` стоит **50 Telegram Stars**.

Схема работы:

1. Пользователь отправляет `/username имя` или `/scan example.com`.
2. Бот создаёт счёт на 50 ⭐ в валюте `XTR`.
3. До `successful_payment` поиск не запускается.
4. После подтверждённой оплаты бот автоматически запускает оплаченный запрос.
5. Платёж и заказ сохраняются в SQLite, включая `telegram_payment_charge_id`.
6. Если бот перезапустился или процесс упал после оплаты, `/retry` повторяет оплаченный незавершённый запрос без новой оплаты.

Цена меняется переменной `PRICE_STARS`, но для текущей модели оставь `50`.

## Команды

- `/start` — справка
- `/username example` — создать оплату и после неё найти публичные профили через Maigret
- `/scan example.com` — создать оплату и после неё запустить SpiderFoot
- `/retry` — повторить уже оплаченный, но не завершённый запрос
- `/cancel` — остановить свой текущий процесс
- `/terms` — условия оплаты
- `/support` — информация о поддержке

## Переменные окружения

Обязательно:

```env
BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
```

Для публичного платного бота обычно `ALLOWED_USER_IDS` оставляют пустым. Если бот нужен только ограниченному списку пользователей:

```env
ALLOWED_USER_IDS=123456789,987654321
```

Настройки:

```env
MAX_CONCURRENT_SCANS=1
SCAN_TIMEOUT_SECONDS=300
RATE_LIMIT_SECONDS=30
REPORT_TTL_HOURS=24
PRICE_STARS=50
SUPPORT_TEXT=По вопросам оплаты и работы бота обратитесь к владельцу бота.
```

## Запуск через Docker

```bash
docker build -t osint-telegram-bot .
docker run --rm \
  -e BOT_TOKEN="YOUR_TOKEN" \
  -e PRICE_STARS="50" \
  osint-telegram-bot
```

Во время сборки Docker устанавливает Maigret 0.6.5 из PyPI и загружает официальный SpiderFoot 4.0 с GitHub. Они устанавливаются в отдельные virtualenv, потому что их зависимости конфликтуют.

## Amvera

В корне уже есть `Dockerfile`, поэтому проект можно подключить к Amvera как Git-репозиторий и выбрать Docker-сборку. После подключения добавь `BOT_TOKEN` и `PRICE_STARS=50` в переменные окружения приложения.

Боту не нужен веб-порт: он работает через Telegram long polling.

**Важно для платежей:** база заказов хранится в `data/payments.sqlite3`. Для продакшена на Amvera каталог `data` должен находиться на постоянном хранилище, иначе при пересоздании контейнера можно потерять локальную историю заказов и платежей. Telegram всё равно хранит факт платежа у себя, но бот должен сохранять `telegram_payment_charge_id` для корректной поддержки и возможных возвратов.

## Безопасность

- токен не хранится в репозитории;
- команды запускаются без shell-интерпретации;
- ввод username/target валидируется;
- loopback/private/link-local/reserved IP-адреса отклоняются;
- есть ограничение частоты создания счетов и параллелизма;
- счёт привязан к пользователю, который его создал;
- перед выполнением проверяются `XTR`, сумма и payload;
- повторно обработанный платёж не запускает второй бесплатный запрос;
- пользователь может остановить только свой текущий процесс.

Используй инструмент только для открытых данных и целей, которые тебе разрешено проверять.
